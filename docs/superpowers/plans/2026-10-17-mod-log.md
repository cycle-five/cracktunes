# Mod Log Implementation Plan

> **Amended during the build.** The attribution and batching rules in this plan were changed by rulings M1 and M5–M26 while it was executed (the SDD ledger has each one). Where this plan and the spec disagree, the amendment bullets in spec §2.3 are authoritative. In particular "D > L → as D = L" below is superseded: D > L logs nothing (M8c).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a per-server "who modded me?" log channel. It shows server mutes and deafens exactly, forced disconnects and moves as attributed from the audit log, and every room kick, mute, unmute and let-back-in, with the actor and the reason. Ships as v0.29.0, stacked on PR 1 (voice rooms, ct#607).

**Architecture:** a new `crack-core/src/modlog/` module.
- **Pure core:** a typed `ModLogEvent` and its renderer, and a pure `attribute()` that turns audit-log count deltas plus observed voice changes into attributions.
- **Thin glue** feeds it from three sources:
  - `GuildAuditLogEntryCreate`, for mutes and deafens;
  - debounced audit-log fetches after voice leaves and moves, behind an `AuditSource` seam with a recording fake;
  - `rooms::ops::act`, for room actions.
- **Output and settings:** posts go through the courier to the configured channel. Settings live in their own table, with the "never save over unread settings" guard PR 1 introduced.

**Tech Stack:** Rust 2021, serenity `next` (37b9f43: `Http::get_audit_logs(guild, action_type, user, before, after, limit)`, `AuditLogEntry { id, action, user_id, target_id, reason, changes, options{count, channel_id} }`, `Change::Mute`/`Change::Deaf`), poise, sqlx 0.9/Postgres, axum (crack-web).

**Spec:** `docs/superpowers/specs/2026-10-16-voice-rooms-and-mod-log-design.md`. This plan covers section 2 (mod log), plus the mod-log halves of sections 3 (dashboard) and 4 (docs). Read section 2 before any task.

## Global Constraints

- Off by default. It needs a database (enabling without one → refused, as for rooms). Free on every server.
- **Logged:**
  - server mute and unmute, and server deafen and undeafen, from `MEMBER_UPDATE` (24) with a `mute`/`deaf` change: exact, with the actor and the audit reason;
  - forced disconnects (`MEMBER_DISCONNECT` 27) and moves (`MEMBER_MOVE` 26), attributed;
  - room Kick (reason required), LetIn, Mute (optional reason) and Unmute: exact.
- **Never logged:**
  - self-mute or self-deafen;
  - voluntary leaves (an audit delta of 0 → nothing);
  - CrackTunes' own voice changes;
  - audit entries the bot itself authored, as attribution candidates.
- **Attribution rules (spec 2.3):**
  - a `target_id` naming a changed member pairs exactly;
  - otherwise, with D the summed positive count deltas (bot-authored excluded) and L the unexplained changes:
    - D = 0 → nothing;
    - D = L → each `By(actor)`, or `OneOf(actors)` when several actors acted;
    - D < L → one `DisconnectBatch`;
    - ~~D > L → as D = L, with the excess logged at debug;~~ superseded (M8c): D > L logs nothing;
  - moves are matched per destination (`options.channel_id`).
- **Timing:** a debounce of 2 s after the last change in a burst, capped at 5 s after the first. A room kick holds an expected disconnect for 10 s. A 403 suspends fetches for 10 min, or until settings are saved again.
- **Fetch limit:** `limit=10` per fetch, per action type. At most one fetch in flight per guild. Work happens only for guilds with the mod log enabled: nothing on any event for the rest.
- **Snapshot:** per guild and action type, `entry id → count`. It is seeded when the mod log becomes active (at `GuildCreate` for enabled guilds, and at enable time), so the first forced action is attributable.
- **Rendering:** one embed per event, mentions inside the embed, `Mentions::None` (no pings), timestamped. An attributed disconnect or move carries the footer "Matched from Discord's audit log by timing".
- **Repo rules (same as PR 1):**
  - strings → `pub const` in `crack-core/src/messaging/messages.rs`;
  - sends through `messaging::courier`/`Transport` only;
  - typed serde (no `json!`/`Value` for owned data);
  - ids parsed defensively (reject 0 and `u64::MAX`);
  - migrations in BOTH `migrations/` and `crack-core/test_migrations/`;
  - `.sqlx` via `scripts/sqlx_sync.py`;
  - never `git add -A`;
  - commit trailer exactly `Co-Authored-By: Claude & Lothrop (cycle.five@proton.me)`;
  - sabotage every new test;
  - assert on what is sent;
  - no source-scan tests;
  - no stray background processes.
- **Gate per task:**
  - `cargo +nightly fmt --all -- --check`;
  - `cargo clippy --workspace --all-targets --features crack-core/db-tests -- -D clippy::all -D warnings --allow clippy::needless_return`;
  - the focused tests;
  - DB tests use the local postgres at 127.0.0.1:5432 (postgres/mysecretpassword/postgres), with `docker --context default` if needed.

## Review Focus

1. **A burst of leaves at once:** several people leave voice together and one moderator disconnected two of them. That gives one `DisconnectBatch` naming the actor and the candidates, and never a wrong `By`. Test: Task 3 `fewer_deltas_than_leaves_is_a_batch`.
2. **Restart:** the first forced disconnect after startup is still attributed (the snapshot is seeded at `GuildCreate`). Test: Task 4 `seeded_snapshot_attributes_the_first_disconnect`.
3. **A server that never enabled the mod log pays nothing:** no audit fetch, no batching state, on any voice event. Test: Task 5 `disabled_guild_records_nothing_and_fetches_nothing`.
4. **The bot's own room kick:** it is logged once, as the room action with the actor and reason. It is never also logged as an audit-attributed disconnect by CrackTunes. Test: Task 6 `room_kick_is_logged_once_with_its_reason`.
5. **CrackTunes lacks View Audit Log:** fetches 403 → suspended. `/modlog status` and the dashboard say what is missing. Nothing spams the log. Test: Task 4 `forbidden_suspends_fetching`.

### Task 3: Attribution

**Files:** Create `crack-core/src/modlog/attribution.rs`.

**Interfaces:**
- Produces:
  ```rust
  #[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)] pub enum AuditKind { Disconnect, Move }   // 27, 26
  #[derive(Debug, Clone, PartialEq, Eq)]
  pub struct AuditRow { pub id: u64, pub kind: AuditKind, pub actor: Option<UserId>, pub target: Option<UserId>,
                        pub count: u32, pub channel: Option<ChannelId> }
  #[derive(Debug, Clone, Default, PartialEq, Eq)]
  pub struct Snapshot { pub seeded: bool, pub counts: HashMap<u64, u32> }   // per (guild, kind)
  #[derive(Debug, Clone, PartialEq, Eq)]
  pub enum Change { Left { target: UserId, from: ChannelId }, Moved { target: UserId, from: ChannelId, to: ChannelId } }
  pub fn attribute(snap: &Snapshot, rows: &[AuditRow], changes: &[Change], bot: UserId) -> Vec<ModLogEvent>;
  pub fn advance(snap: &mut Snapshot, rows: &[AuditRow]);   // record counts; seeded = true
  ```
  `attribute` applies spec 2.3 exactly:
  1. Rows authored by `bot` (or with no actor) never count.
  2. A row id missing from a seeded snapshot is new, so its delta is its count. On an unseeded snapshot, nothing is attributed: the snapshot is only seeded.
  3. Exact pairs: a row whose `target` names a changed member pairs with that change and consumes one unit of that row's delta.
  4. Leaves form one group. Moves group by destination (`row.channel` vs `Change::Moved.to`).
  5. Within each group, D vs L:
     - 0 → nothing;
     - D = L → each change `By(a)` when one actor, else `OneOf(actors sorted)`;
     - D < L → leaves: one `DisconnectBatch { actors, count: D, among: targets }`; moves: nothing (logged at debug), because a wrong move attribution is worse than none;
     - ~~D > L → as D = L, with the excess logged at debug.~~ Superseded (M8c): D > L logs nothing.

### Task 4: The audit source, batching, seeding and preflight

**Files:** Create `crack-core/src/modlog/audit.rs`, `crack-core/src/modlog/batch.rs`, `crack-core/src/modlog/preflight.rs`. Modify `crack-core/src/modlog/registry.rs`.

**Interfaces:**
- Produces:
  ```rust
  #[derive(Debug, Clone, PartialEq, Eq)] pub enum AuditError { Forbidden, Other(String) }
  #[async_trait] pub trait AuditSource: Send + Sync {
      async fn recent(&self, guild: GuildId, kind: AuditKind, limit: u8) -> Result<Vec<AuditRow>, AuditError>;
  }
  pub struct LiveAudit { pub http: Arc<Http> }   // get_audit_logs(guild, Some(26|27), None, None, None, Some(limit)); entries → AuditRow; 403/50013 → Forbidden
  // test_support: FakeAudit { scripted responses per (guild, kind), recorded calls }
  // batch.rs
  pub const DEBOUNCE: Duration = Duration::from_secs(2); pub const MAX_WAIT: Duration = Duration::from_secs(5);
  pub const SUSPEND: Duration = Duration::from_secs(600);
  pub fn record_change(data: &Data, audit: Arc<dyn AuditSource>, sink: Arc<dyn ModLogSink>, guild: GuildId, change: Change, now: Instant);
  pub async fn flush(data: &Data, audit: &dyn AuditSource, sink: &dyn ModLogSink, guild: GuildId);   // the debounced fire
  pub async fn seed(data: &Data, audit: &dyn AuditSource, guild: GuildId);                          // fetch BOTH kinds → advance(snaps, &[Disconnect, Move], rows)
  #[async_trait] pub trait ModLogSink: Send + Sync { async fn post(&self, guild: GuildId, e: ModLogEvent); }
  // preflight.rs
  pub const NEED_GUILD: Permissions = VIEW_AUDIT_LOG;
  pub const NEED_CHANNEL: Permissions = VIEW_CHANNEL | SEND_MESSAGES | EMBED_LINKS;
  #[derive(Debug, Clone, PartialEq, Eq)] pub enum ModLogFinding { MissingServer(Permissions), MissingChannel { channel: ChannelId, perms: Permissions }, Suspended }
  pub fn preflight(bot_guild: Permissions, bot_in_channel: Option<Permissions>, channel: Option<ChannelId>, suspended: bool) -> Vec<ModLogFinding>;
  pub fn for_guild(cache: &Cache, data: &Data, guild: GuildId) -> Option<Vec<ModLogFinding>>;
  ```
  The registry gains:
  - per-guild `pending: Vec<Change>` with `first_at`, a debounce `AbortHandle`, and an `in_flight` flag;
  - snapshots `(GuildId, AuditKind) → Snapshot`;
  - `suspended_until: Option<Instant>`;
  - `expected: DashMap<(GuildId, UserId), Instant>`, used by Task 6, with `expect_disconnect(g, u, now)` and `take_expected(g, u, now) -> bool` (10 s).

  `record_change`:
  - drops the change for a guild that isn't enabled, or that is suspended;
  - drops a change whose target has an unexpired expected disconnect, and consumes it;
  - otherwise appends it and (re)arms the debounce: the earlier of last+2 s and first+5 s.

  `flush` (rulings M8b, M9, M10):
  - fetches only the kinds present in the pending set, with `limit 10`;
  - takes the pending changes AFTER the fetch returns (changes that arrived meanwhile join this batch);
  - calls `attribute(&snaps, ..)` with the per-kind `Snapshots`, then `advance(&mut snaps, &fetched_kinds, &rows)`;
  - when a suspension lifts, the next flush RE-SEEDS (calls `seed`) instead of diffing against the pre-suspension snapshot, and drops the batch;
  - on `Forbidden` → suspend 10 min and drop the batch;
  - otherwise `attribute` → `sink.post` for each event, then `advance`.

  A save of mod log settings clears the suspension.
