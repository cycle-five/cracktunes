# v0.13.1 patch batch — design

**Date:** 2026-09-19 · **Branch:** `fix/v0.13.1-batch` from master `d50705e4`
**Issues:** #480, #494, #468, #523, #472

Five issues, one patch release. Three are user-visible bugs (a panic, a stray
message, a failure that leaves no trace); two are hygiene that has already cost
CI runs. Every root cause below was re-verified against `d50705e4` before this
was written — the last issue trim found six fixed-but-open issues, so no issue
text was trusted on its own.

## What the investigation found

Where this section disagrees with an issue body, this section is correct.

### #480 — one unwrap left, now with five callers

Only `force_skip_top_track` (`crack-core/src/commands/music/skip.rs:195`)
remains; the rest of the issue was fixed in v0.12.1.

```rust
handler.queue().current().unwrap().stop().ok();
```

Callers: `/skip`, `/downvote`, `/voteskip`, and `/gp` twice. A track that ends
naturally between the caller's non-empty check and this line empties the queue
and panics a tokio worker. Every line *after* the unwrap is already safe on an
empty queue: `dequeue(0)` returns `None`, `resume()` is a no-op, and
`current_queue()` returns an empty `Vec`.

The race is reproducible without timing: call the function on a `Call` whose
queue is already empty, which is the state the race leaves behind.
`Call::standalone` gives a real songbird queue (`handlers/track_end.rs:527`
already does this), and `Data::lock_queue` yields the `QueueGuard`.

### #494 — four bare `?` between the send and the edit

`doplay.rs` sends the placeholder at `:484` and edits it into the result at
`:551`. Between them, `query_type_from_url` (`:488`), `verify` (`:495`),
`match_mode` (`:524`) and `build_play_reply` (`:547`) each return early with
the placeholder still posted. `get_metadata.rs:44` has the same shape with three.

On a command error, the framework's `FrameworkError::Command` arm
(`config.rs:48`) already sends the error as its own message. So the placeholder
must be **deleted**, not edited into the error — editing would report the
error twice.

`match_mode` receives the handle and, for playlists, edits it with progress
(`Queued N/M`) before it can fail mid-list. Deleting it then loses that line;
the queue and the floating status message still show what landed. Accepted.

### #468 — three refusal arms, one shape

`gp.rs:3143` (`submit`), `:3398` (`voteskip`), `:3459` (`votefull`) all read
`Err(e) => CrackedMessage::CrackedError(e)` (the votes wrap it in a tuple).
None logs. The ephemeral replies are correct and stay.

`tracing-subscriber` is already a crack-core dev-dependency, so a test can
install a capturing subscriber. No capture helper exists yet.

### #523 — seven tests, not four

Found empirically, not by grep: the full workspace suite was run inside a
loopback-only network namespace (`unshare -rn`), with the locally cached
`crack-core/data/*.json` moved aside first — that cache is what makes the phone
test pass on a developer machine.

**Fail with no network (4):**

| test | in #523? |
|---|---|
| `lib_test::test_phone_code_data` (`lib.rs:784`) | yes |
| `test::structs::test::test_phone_code_data` (`test/structs.rs:7`) | **no** |
| `http_utils::test::test_resolve_final_url` (`http_utils.rs:345`), example.com | yes |
| `test::http_utils::test::test_resolve_final_url` (`test/http_utils.rs:6`), a live `spotify.link` redirect asserted down to its `_branch_match_id` | **no** |

**Pass offline, reach the network online (3):**

| test | problem |
|---|---|
| `errors.rs:587` | `if let Err(e) = send(...) { assert!(...) }` — a resolver that answers for `notreallol` silently skips the assertion |
| `errors.rs:699` | two sends that can disagree; the fallback arm unwraps expecting a 403 |
| `vote.rs:118` `test_fail` | asserts `is_ok() \|\| is_err()`, a tautology, after a live top.gg call |

🪤 **"Passes offline" is necessary, not sufficient.** An offline run catches a
test that *needs* the network; it cannot catch one that merely *uses* it and
tolerates failure. The last three are fixed by removing their I/O, verified by
reading.

**The phone fixtures are tracked, at the wrong path.** `data/phone.json` and
`data/names.json` sit at the repo root; `cargo test -p crack-core` runs with the
crate as its working directory, so `./data/phone.json` resolves to the
gitignored `crack-core/data/` and the test downloads over plain HTTP.

**Also found, deferred:** `vote.rs` `test_check_and_record_vote` runs under
`db-tests` — which CI's Build job enables — and reaches the live top.gg API via
`has_voted_bot_id`. Mocking it needs the top.gg base URL made injectable, a
larger change than this batch. #523 is **narrowed, not closed**: it keeps this
test and #302's ignored crack-testing YouTube tests.

`CrackedError`'s `PartialEq` compares any two `Reqwest` errors by variant alone
(`_ => discriminant(..)`), so replacing network errors with builder errors in
the `errors.rs` tests preserves exactly what they assert.

### #472 — sixteen attributes, not seventeen

`queue_resolved_track_back_old` was already deleted by #479. Stripping all 16
and compiling — default features, then `crack-bf,crack-osint` — sorts them:

| class | sites |
|---|---|
| stale: item is used, drop the attribute | `register.rs:58` `register_globally_cracked` (called at `serenity.rs:114`); `crack-testing/src/resolve.rs:25` `user_id` (read at `:167`) |
| dead, compiler-confirmed | `lib.rs:297`/`:299` `phone_codes`/`country_names`; `help.rs:152` `HelpCommandMode`; `bf.rs:71` `ascii_art_number` (feature `crack-bf`); `guild/settings.rs:27` `PIPED_WATCH_URL`; `serenity.rs:587` `check_delete_old_messages`; `handlers/voice.rs:21` `Handler`; `crack-testing/src/lib.rs:96` field `video_opts`; `crack-cli/src/main.rs:259` `init_logging` |
| dead, **invisible to the compiler** | `register.rs:72` `register_in_guild_cracked` and `:98` `register_application_commands_cracked` (zero callers); `resolve.rs:23` `queued` (written, never read) |
| parked on purpose, with a comment saying why | `serenity.rs:547` `log_system_load`; `crack-voting/src/lib.rs:253` `MIGRATOR` |

All strips done together, not one at a time: rustc treats an allowed item as a
live root, so something used only by another allowed item stays hidden until
both are stripped.

🪤 **#472's method has a blind spot.** "The compiler answers each one" is false
for a `pub` item in a library crate: rustc never reports those as dead, because
another crate might call them. The three rows in the invisible class were found
by grep.

## Design and rulings

**Owner decision — delete `PhoneCodeData` from crack-core.** Its consumers,
`phcode.rs` and `phlookup.rs`, left with crack-osint; `load()` is never called in
production, where both construction sites use `::default()`. Under the
extraction contract, data and logic belong in the module crate and only the
poise wrapper stays in crack-core. A revival rebuilds it inside crack-osint
(crack-osint#3). Removes two of #523's failing tests and two of #472's rows.

**Ruling — #480: an empty queue counts as already skipped.** Stop the current
track only if there is one. The function is written best-effort throughout, the
caller's intent is satisfied, and `NothingPlaying` would be wrong to show
someone who just watched a track end. *Costs if wrong:* a caller that needed to
know nothing was stopped gets `Ok` and an empty queue; none of the five does.

**Ruling — #494: one owner for the placeholder, by control flow.** Everything
fallible after the send moves into one inner function whose `Result` passes
through a single cleanup site that deletes the placeholder on `Err`. A `?`
added inside that function later is covered without being listed — the
property #494 asks for, rather than a survey of today's four sites. The covered
region **ends at the successful edit**: once the placeholder has become the
reply, a later failure (the partial-listing footnote, the status move) must not
delete it. Applied to `/play` and `/get_metadata`.

The combinator is tested with a fake placeholder; the wiring is structural. A
test driving `play_internal` itself would need a Discord mock. *Costs if wrong:*
a `?` added between the send and the combinator escapes it, so the two lines
stay adjacent with a comment saying why.

**Ruling — #468: one function logs and builds the reply.** All three arms call
it, so the log and the reply cannot drift apart and a fourth refusal site gets
both or neither. `warn!` with command, user, guild and error; the reply stays
ephemeral.

**Ruling — #523: loopback, not the internet.** One redirect test against a
local server replaces both `resolve_final_url` tests: a short link is a
redirect chain, and asserting on `spotify.link`'s live output tests Spotify.
The `errors.rs` tests take builder errors, made with no I/O by
`reqwest::Client::new().get("not a url").build()`. `test_fail` is deleted: a
tautology cannot be given a real assertion without the mock that is deferred.

**Ruling — #472: the two parked items become `#[expect(dead_code, reason = …)]`.**
This is the structural fix for the failure #472 describes. `query_type_from_url`
kept a vestigial `allow` for 21 months because nothing notices when an allow
stops being needed. An `expect` does: the day the item gains a caller, the
compiler raises `unfulfilled_lint_expectations`, and CI's `-D warnings` fails
until the attribute goes. Everything else in the census is removed.

No test is written for any #472 deletion. A deleted item has no behaviour to
test, the compiler under `-D warnings` is the check, and a test that scans
source for `allow(dead_code)` is the kind the owner has vetoed.

## Out of scope, recorded

- **A second race in `force_skip_top_track`, which double-skips rather than
  panics.** If a track ends and songbird auto-advances in the window,
  `current()` returns the *next* track and this skips it too. The lease cannot
  prevent it, since songbird advances on its own driver.
- **`CommandPanic` never replies** (#494's "Related"): a panic still leaves the
  placeholder and tells the user nothing.
- **`get_metadata.rs` unwraps `YouTube::new_with_options`.**
- **reqwest's `blocking` feature.** This batch removes crack-core's last three
  uses, but the feature is enabled in the workspace spec, in crack-testing and in
  crack-types, and rusty_ytdl has its own, so dropping it is a workspace change.
